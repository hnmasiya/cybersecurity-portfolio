Wazuh Agent -> Manager Connection Evidence
============================================

Architecture: Windows Server 2022 VM (Azure, "dc01-lab") -> Tailscale mesh
VPN -> Wazuh Manager (Docker, home lab, Zorin OS)

Tailscale IPs:
  dc01-lab (Azure VM):             100.79.229.99
  normann-thinkpad-x260 (Manager): 100.104.119.57

Tailscale ACL: a rule was added scoping access to exactly
  src 100.79.229.99 -> dst 100.104.119.57, ports 1514/1515
The home tailnet's ACL is default-deny once any rule exists; the only
pre-existing rule allowed a tagged RustDesk client on unrelated ports, so
the new agent traffic needed an explicit allow.

The "A process was created" volume is almost entirely the built-in Security
Configuration Assessment (SCA) scan spawning auditpol.exe/conhost.exe
repeatedly while it evaluates the CIS benchmark - background scan noise,
not attacker activity. The CIS benchmark alerts are genuine SCA policy
evaluation results against the real hardening baseline applied earlier by
Harden-WindowsServer.ps1.

--- 5. Agent group membership ---

Groups (2):
  default (1)
  windows-sysmon (1)

The agent was moved from default-only into the pre-existing windows-sysmon
group (see SIEM/Wazuh/Reports/Wazuh-Live-Server-Integration.md), which had
been configured on the Manager but unused pending a live Windows endpoint.
Wazuh merges shared configuration from every group an agent belongs to, so
dc01-lab now also collects via that group's Windows Security / Sysmon /
PowerShell / Windows Defender event channel configuration, on top of its
own default config. The agent was restarted after the group change and
reconnected cleanly.
