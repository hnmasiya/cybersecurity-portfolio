# DVWA — Weak Session IDs

## Objective

Assess the randomness and predictability of session identifiers generated by DVWA and determine the risk of session prediction or hijacking.

## Skills & Tools

- DVWA
- Browser
- HTTP request analysis
- Linux
- Git

## Architecture

DVWA is a deliberately vulnerable PHP/MySQL web application deployed in the local cybersecurity laboratory on a Zorin OS host.

## Topology

**Target:** `http://localhost:8081`

**Environment:** Local isolated cybersecurity laboratory.

## Execution

The Weak Session ID module was accessed at the Low security level. Multiple session identifiers were generated and compared for predictability.

## Walkthrough

1. Opened the Weak Session ID module.
2. Generated multiple session identifiers.
3. Recorded the generated values.
4. Compared their structure and sequence.
5. Assessed whether the values demonstrated predictable behaviour.
6. Captured evidence.

## Attack Simulation

The controlled assessment simulated an attacker attempting to identify predictable session identifiers.

## Detection

Monitor for:

- Reuse of session identifiers.
- Concurrent use from different source addresses.
- Unusual session transitions.
- Predictable session-generation patterns.

## Triage

Prioritize according to the privileges and sensitivity of accounts whose sessions could potentially be compromised.

## Investigation

Review session logs, source addresses, user agents, timestamps, and concurrent session activity.

## Findings

The DVWA Low-security implementation is intentionally designed to demonstrate weak session identifier generation. The available repository evidence documents the Weak Session ID module page. A separate session-sequence analysis screenshot is not currently available, so the report does not claim that such an image exists.

**Finding:** Weak session identifier generation.

**Risk Rating:** Medium

## Impact

Predictable session identifiers may increase the risk of:

- Session prediction.
- Session hijacking.
- Unauthorized access to authenticated resources.
- Authentication control bypass.

## Root Cause

Session identifiers are generated using insufficiently unpredictable values.

## MITRE ATT&CK

**T1539 — Steal Web Session Cookie**

## Remediation

- Use cryptographically secure random session identifiers.
- Regenerate session IDs after authentication.
- Set Secure and HttpOnly cookie attributes.
- Use SameSite cookie protection.
- Expire inactive sessions.

## Validation

Generate a large sample of session identifiers and confirm that they demonstrate sufficient unpredictability and entropy.

## Lessons Learned

The assessment demonstrated the importance of secure session management and the risks associated with predictable authentication tokens.

## Recommendations

Combine secure token generation, cookie security controls, session rotation, timeout policies, and monitoring for anomalous session activity.
