# 3. Agent Deployment Process

The endpoint is the deployed Azure Windows Server 2022 Domain Controller
(`dc01-lab`, see [Azure Windows Server Lab](../../../Cloud-Security/Azure-Windows-Server-Lab/README.md)),
and the Manager is the Docker-based Wazuh stack running on the home lab
(Zorin OS). The two are on separate networks, so the deployment process
was:

1. Installed Tailscale on both the Manager host and the Azure VM, joining
   both to the same private mesh network without opening any port on the
   home router.
2. Added a Tailscale ACL rule scoping the Azure VM's access to exactly the
   Manager's agent ports (1514/1515) - the home tailnet is default-deny
   once any ACL rule exists.
3. Installed the Wazuh Agent (matching the Manager's 4.14.7 version) via
   [`Install-WazuhAgent.ps1`](../../../Cloud-Security/Azure-Windows-Server-Lab/Scripts/Install-WazuhAgent.ps1),
   pointed at the Manager's Tailscale IP.
4. Verified auto-enrollment and connection from both the agent's own log
   and the Manager's `agent_control` CLI.
5. Moved the agent from the `default` group into the pre-existing
   `windows-sysmon` group (Windows Security/Sysmon/PowerShell/Windows
   Defender channel collection) and restarted it to confirm the merged
   config synced.

# 5. Validation

Validation included:

- Confirming agent registration and "Active" status via `agent_control -lc`
  on the Manager
- Confirming the agent's own log shows a successful connection
  (`Connected to the server`, `Agent is now online`)
- Reviewing real alerts generated by Wazuh's rule engine from the agent's
  telemetry, including a MITRE-mapped authentication event (T1078, Valid
  Accounts) and genuine CIS Windows Server 2022 Benchmark SCA findings
- Confirming group reassignment and reconnection after moving the agent
  into `windows-sysmon`
